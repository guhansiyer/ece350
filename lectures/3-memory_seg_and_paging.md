# Memory Segmentation and Paging

## Memory Segmentation

Each element of memory (stack, heap, C std. lib) are known as **segments**.

A full program has a collection of different sized segments, which are generated by the compiler:

1. The code
2. Global variables
3. The heap
4. The stack (one per thread)
5. The C standard library

Instead of thinking about memory as a pure address, we can think of it as a tuple: (segment, offset).

For this, we need an implementation to map these tuples into memory addresses. The mapping has a segment table.

Each entry in this table has a base and limit value.

With segmentation, memory does not need to be contiguous. Different parts of a program can be allocated in different segments.

## Paging

Fixed and variable sized partitions suffer from fragmentation. To solve this, we divide memory into small, fixed chunks of equal size, called **frames**, and divide each process's memory into chunks that are the same size as a frame, called **pages**. Then, each page can be assigned to a frame. A frame can be empty or have exactly one page in it.

> Analogy: picture frame.

A picture frame may be empty or contain a picture. If the frame is empty, it is only necessary to put a picture in it. To put in a different picture, take out the picture that is already there. Taking out the picture to empty the frame is allowed. A picture must be aligned to be completely in the frame.

## Paging: Process Initialization

A process starts, is loaded into memory and has initial memory requirements.

The number of pages can and will change over time as memory is allocated and freed.

A process may be swapped to disk, but must be swapped back in to run.

A process takes up a certain number of pages in memory at any time.

Pages separate the logical address from physical addresses. Programmers may pretend a computer's address space is $2^{64}$ bytes rather than however many GB of memory are in the machine.

## Page Tables

Since we have multiple segments per process and they are no longer continuous, a base and limit address are insufficient.

Each process needs a page table to keep track of which pages are located where in memory, as well as which frames are free.

Page size is usually a power of 2, making translations between logical addresses and tuples (page number and offset).

If a logical address has size $2^m$ and page size $2^n$ bytes, the high order $m - n$ bits of the logical address are the page number, the lower $n$ bits are the page offset.

External fragmentation is eliminated with this scheme, because all pages are the same size.

Page size is usually correlated with disk block size, so that swapped pages can be read/written with a single operation.

This all contributes to the answer to why application developers can treat memory as if it is infinitely large and unshared: because a program is scattered throughout physical memory but appears contiguous to running applications and the developer.

## Shared Pages

Another advantage of paging is sharing common code.

Users often have multiple programs open; in multi-user systems different users may have the same programs open.

We can reduce memory consumption if common parts of a program are shared between all instances of it.

> Example: vi

Imagine that 5 users on a system want to use `vi`. The program itself uses 10 pages on its own.

Without sharing, we need 50 pages to satisfy all users.

If we can share the 10 pages, we have saved 40 pages of memory.

Similarly, other code such as libraries, compilers and OS utilities can be shared.

Any code can be shared as long as it is **reentrant**; unchanging when executed. This means that the code maintains no state.

## Page Table Structure

A page table, at its core, is just a standard table. If a system is 32-bit and page sizes are 4 KB ($2^{12}$), then the page table has $2^{32} / 2^{12} = 2^{20}$ pages (~1 million entries).

Given that page tables themselves can be so large, there are strategies for structuring the page table. Three examples include:

1. Hierarchical paging
2. Hashed page tables
3. Inverted page tables.

### Hierarchical Paging

Rather than have one large table, the table has multiple levels that can be broken up.

Suppose we have a two level system. If the page number is $p$, the first $k$ bits indicate the outer page. The outer page contains some information about where the *inner* pages are. The remaining $p - k$ bits identify the inner page. After the inner page is identified, the displacement $d$ is then calculated from the inner page.

### Hashed Page Tables

Each entry in the page table acts as a "bucket", implemented as a linked list. A hash function assigns pages to buckets.

### Inverted Page Tables

Instead of keeping track of the pages in the entries, we keep track of the frames. Each entry tracks the associated process and page numbers. This saves massive amounts of space for larger systems (64-bit). The drawback is that we can no longer find pages by looking at the address, we must search the entire table.

## Hardware Support

Modern computers have hardware support to aid memory accesses.

The simplest page table implementation uses a series of dedicated registers.

In modern machines, the page table is kept in main memory, and a single register is used to point to the page table.

The catch with this is that this requires two memory accesses for each read/write operation: first we have to find where the page is by accessing main memory, then we have to look in the page table to find the frame where the page is stored.

The solution to this is, again, hardware. A fast cache called the translation lookahead buffer (TLB), acts as a key-value store, where the key is the logical address (page number) and the value is the physical address (frame number). The search is fast because all comparisons are done simultaneously. To prevent the search from becoming expensive, the TLB has limited size; around 32 to 1024 entries.

On a memory read/write, the page number is checked against the TLB. If it is found there, the frame number is immediately known. If it is not found there, it is a TLB miss and the full table must be searched.
